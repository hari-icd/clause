# Clause — power-use notes

Living list of the tricks that make the loop fast. Every time we find a loophole that saves clicks, tokens or rounds, it goes here *and* into the tooling, so it survives new sessions and new machines. (Claude: read this at session start; add to it whenever a new trick lands.)

## The loop
- `npm run live` once. Save a screen JSON → Figma frame rebuilds in ~1–3s, HTML export follows. No tool calls to "build".
- Plugin **Start (silent)** stays hidden; ⌘⌥P (Ctrl+Alt+P) reruns the last plugin after any plugin change.

## Talking to Claude from Figma (costs nothing while idle)
- One chat pane. **◎ annotate** on → the Figma selection rides along as chips (multi-select OK; one comment covers all; prompt carries node id, component, props, path, screen). ⏎ queue · ⌘⏎ send now. Queue widget: hover an item for send/discard; header icons send/discard all. History is local (`.clause/history.json`), never in the Figma file.
- ⚙ in the header: build status, drop an HTML export to rebuild it, exports listing.
- **Listener**: say "listen" → Claude arms `npm run inbox -- --watch` (a blocked node process, zero tokens while idle; one normal turn when something arrives; expires after 30 min with one tiny notice). Without it, say "check ib".
- Claude answers with `npm run reply -- "…"` → shows in the Messages tab.

## Reading Figma without burning context
- `node scripts/inspect.mjs <url|nodeId>` → `drafts/<id>.json` skeleton of ANY frame (senior designer work included): catalog keys, non-default props, texts, token-mapped spacing. Start reference screens from this, never from scratch.
- `--vs <mine>` → numeric diff (w/h/gap/pad/radius/props) instead of eyeballing screenshots. `--raw` for layer names inside instances (needed for `ops`).
- `use_figma` reads truncate above ~20 kB — prefer inspect.mjs; if you must, return only ids/names.
- `get_screenshot` on the root frame (maxDimension ≤1200) is the cheapest visual check; never screenshot the page.

## Builder loopholes (runtime.js)
- `ops.nodes` reaches anything inside an instance by layer name + nth: `hide`, `icon`/`swap` (`@icon-key`), `props` (nested variant props, e.g. tab `Current`), `style` + `color` (restyle a text inside a component), `maxLines`, `tint`.
- Readback warnings: `prop not applied …` and `variant not matched …` — a warning is a bug, never ignore.
- `bg: "none"` on any node (instances too) clears its fill — the only way to strip a component's background.
- Instances can't be dashed/outlined differently; need a plain frame for that (record `why`).
- Big library sets import slowly once (~2 min for copilot-input-box), then cached per plugin session.

## New design system
- Plugin ⚙ → **Extract components & tokens** (or the menu item): walks every page + enabled libraries → `ds/components.json`, `variable-keys.json`, `tokens/*`, `tokens.css`, a starter `config.md`. With an existing catalog it writes a preview under `.clause/` and Claude (listener on) compares and recommends the merge. One click replaces the day of manual harvesting.

## Catalog growth
- A component the catalog lacks → add it by main component id (`project-header` was added this way in 2 lines). Prefer `list-item*`, `form-header`, `add-source`, `container`, `featured-icon` over primitives.
- Page-level specs learned from senior frames live in `ds/design-rules.md` (Meetings, Settings pattern). Add one block per new pattern.

## Hygiene
- `npm run clean` wipes `.clause/`, drafts, out, stale exports; `--all` also regenerated files. `npm run setup` on a new machine.
- Nothing in the repo depends on npm packages; Node 18+ only.
- `ops.nodes` `align: right|center|left` right-aligns a text inside a component (sets textAlignHorizontal + parent MAX). Needed for table numeric columns.
- `ops.nodes` `has: "<text>"` selects the nearest instance that contains that text (hide/props it) — use when layer names repeat (menu items, list rows).
- Molecules exist for most "atom stacks": Split Button Brand (`split-button-brand`), Dropdown Menu (`dropdown-menu`). Check the catalog for *-menu / split-* before composing from atoms.
- `ops.nodes` `show: true` reveals a layer the component hides by default (e.g. a 5th menu item); text arrays then include it. Ops run BEFORE text overrides, so `has:` must match the component's original text.
- **Incremental rebuild**: top-level nodes whose JSON (plus catalog/runtime salt) is unchanged are moved from the previous frame instead of rebuilt (`es-hash` plugin data). Unchanged screen ≈ 60 ms; a content edit rebuilds only `main` (nav reused). Keep the nav / overlays as separate top-level children so they stay reusable.
- Per-instance layer index (`idx`) + font preload: ops/texts no longer walk the instance per op.
- Presence/stop: while Claude works the composer send button turns into ■ (Esc also stops); send icon is ↵. ⌄ collapse sits top-left (opposite ☰) and shrinks the window to just the two corner icons.
- Collapsed = ⌃ expand (left) + a bare three-dot status on the right, no container: dots wave in blue while Claude works or a build runs, sit still and grey when idle, red when the server is offline.
- Plugin window anchoring: `figma.ui.resize` keeps the top-left fixed, so collapse/expand pass `anchor:"br"` and code.js shifts the window with `figma.ui.reposition` — the bottom-right corner stays put wherever the user parked it.
- Builds never switch the user's Figma page: the screen is built on its target page in the background (page pin / existing page / current page) and the plugin shows a blue "Built <screen> on <page> — Go ›" nudge (bar when expanded, bouncing chevron when collapsed, 9 s). Only same-page builds zoom the viewport.
- **Layer naming:** component instances keep the component's own name (Buttons/Button Neutral, Routine card…) so the layers panel reads like the DS; frames/text are named by their JSON `i`. The JSON id of every instance is stored in plugin data `es-i`; annotation prompts list it as `target: <id> [layer "<name>"]`, and incremental reuse keys on it.
- **Failed builds never leave frames behind**: every frame a build creates is tracked (`es-root` plugin data + `CACHE.pending`); on failure they are removed (also inside Sections) and the previous frame regains its `es-screen` tag; at the start of the next build Clause-made untagged leftovers are swept. Do **not** loop build retries by hand: one attempt, read the error, fix the cause.
- Files whose library keys no longer resolve: the runtime falls back (a) to the default catalog's key (`alt`), (b) to the main component of an instance already on the target page (donor scan).
- `look.mjs pages|tree|snap|snaps` reads/screenshots whatever file the plugin is open in — no MCP link needed. `"section"` in a screen JSON builds inside a Section; `"ds": "ds/files/<name>"` selects another catalog.

## Announcements build session — what cost time, and the fix (read before building a multi-screen journey)
- **Regenerating screens (gen.mjs) triggers the file watcher for ALL screens**, queueing 11 builds at once (latest-wins drops them mid-build, leaves partial frames). Regenerate, wait, then build one at a time with `/tmp/seq.sh <name>` (push + wait for that name's result). Never edit-regenerate while a build runs.
- **Verify a build by the Designs tree, not only `/result`**: `node scripts/look.mjs tree <sectionId> 1 | grep <title>`. A result "OK" with an old frame id still in the tree means the build did not land.
- **Lint "clean" does not check text styles for alternate catalogs** — compile does: `node -e 'import("./scripts/compile.mjs").then(m=>m.compile("<name>")).catch(e=>console.log(e.message))'` prints the real error when a screen silently never builds (no result, seq.sh times out).
- **Icons for the "-2" file**: use keys present in BOTH catalogs (`icon-close`, `icon-plus`, `icon-announcement`, `icon-user-plus`, `icon-chevron-right`, `icon-upload-cloud`); a key without `alt`/donor fails the whole build.
- **Layers inside an instance**: `node scripts/look.mjs tree <instanceId> 12` (depth >= 9 expands inside instances) to get layer names, then `ops.nodes` `{name, nth, hide:true}`. Donor instances can arrive in a different state (extra toolbars) than the one you looked at.
- **Delete a Clause-built frame**: `curl -X POST "localhost:8787/inspect/<id-with-dash>?remove=1"` (POST; refuses non-Clause frames). Jobs are POST-only and one at a time.
- **Bisect a failing screen**: split into chat-only / preview-only temp screens, delete them after with the remove job.
- Figma "Unable to establish connection" = network, not code: stop, tell the user, do not retry.
- **Listening indicator**: the inbox watcher polls `/inbox` every 1.5s; the server stamps it and `/status` returns `listening` (true if polled in the last 6s). The plugin shows "Claude isn't listening. In Claude Code, type check ib" with a Copy link when false. A Monitor that ends (30 min expiry) must be re-armed, or the banner appears.
- **Designer-made components without auto-layout (e.g. "Small Tabs")** cannot reflow when texts change and children's x cannot be overridden in an instance (`relative-transform`). Fine when labels fit the original widths; otherwise the component itself must be set to auto-layout in the library file. Check `inspect --raw` on the main component: no `lm` = no auto-layout.
- **Real pictures**: a box node takes `"img": "<url>"` (picsum seeded urls like `https://picsum.photos/seed/<seed>/<w>/<h>.jpg`; picsum has no keyword search, only ids/seeds). The server downloads once to `.clause/img/` and inlines base64 because the plugin cannot fetch. gen.mjs helper: `pic(seed, w, h)`. Do not put a `bg` on an `img` box.
- **Silent mode**: eye button in the plugin composer. Silent is ON by default; builds do not scroll/zoom the canvas (`SCREEN.SILENT`, passed with each build message). Needs a plugin reload (⌘⌥P) once.
- **Never wait with an unbounded `until [ lines >= N ]` loop**: if a build prints nothing it spins forever as a hidden background task. Use `/tmp/seq.sh` (each wait is capped at 180s) with run_in_background, or a loop with a counter and a timeout.
- **Multiple design systems**: `ds/registry.json` (file name → system → catalog dir), plugin reports `figma.root.name` on start, server resolves (`/ds/active`, `/ds/file`, `/ds/choose`), switcher icon in the composer, `context:` line at the top of every inbox read, per-system `<dir>/design-rules.md` layered on the shared `ds/design-rules.md`. Add a system by extracting in its file and appending to the registry. Needs a plugin reload once.
- **Add states to a design that was NOT built by Clause** (library-free frames, detached panels): `node scripts/variant.mjs scripts/variants/<spec>.json` clones the existing frames into a new Section (`NEW STATES — …`, re-running replaces it) and varies them: `texts`, `hide`, `fill` (token), `set` (props/text of existing instances), `add` (catalog instances incl. `cursor` for hover), `hideAfter`, `textsAfter`. Faithful to the existing styling because it starts from the real frames. Can't `replace`/insert inside instances. Example: `scripts/variants/clients-review-states.json`. Figma may drop the first call after idle ("Unable to establish connection"): the CLI retries.
- Find layer names of an instance with `look.mjs tree <id> 14`; nth of `Buttons/Button Neutral` etc. counts hidden/header matches too, so verify on a snapshot.
- **Several Figma files open with the plugin**: each plugin instance listens to the same server. Jobs carry `FILE` (the file last reported active) and a plugin ignores jobs for another file; a plugin reports its file when its tab becomes visible and every 5s while visible. Both plugins need a reload (⌘⌥P) after this change.
- **Swap library components in place** (logos, icons): `node scripts/swap.mjs spec.json` with `{swaps:[{target:<node id>, key:<raw component key>, size?, name?}]}`. Get keys from the library file with a read-only `use_figma` (needs the library's Figma link; the plugin cannot list a library's components, only those already used). All Company Logos file key: uncPWhhzIN4jF3Whybo06q (24 logos, plain 128px components named like the company: servicenow, tableau, openai, ms-teams, microsoft-outlook…; no plain "sap", only sap-business-one/concur/hana). Example spec: scripts/variants/website-connector-logos.json.
- **Library dedupe**: `ds-install.mjs` keeps only a file's delta when >=85% of its library components already exist in another catalog (`extends` in ds/registry.json, merged by loadCatalog). Registered files are never re-extracted (UI toast + server 409).
- **Desktop → mobile (360)**: `node scripts/mobilize.mjs <spec>.json` clones a desktop frame and re-flows it: rows that don't fit become columns (kids FILL, gap 16–24), small tile rows wrap, icon+text rows stay rows, fixed heights hug, side padding 20, section padding 100+→60 / 60+→40, type scaled (≥44→×0.75, 36–43→×0.75, 28–35→×0.8, rest unchanged), images keep ratio at 320 wide. Spec: `keep` (marquee rows kept as designed and clipped), `blocks` (replace a block by a clone of the senior mobile reference: header, CTA, footer; `texts` swap copy and can keep italic runs via `[[text, oldSegmentIndex],…]`). Decisions use ORIGINAL desktop widths. Example: scripts/variants/website-embedded-mobile.json. Removing a result: `curl -X POST "localhost:8787/inspect/<id-with-dash>?remove=1"` (names matching "Mobile (360)" are allowed).
- Plugin job results carry `ts`, so two identical errors in a row are still noticed (CLIs used to time out on them). "Unable to establish connection to Figma" after heavy jobs means Figma is busy/offline: wait, do not loop.
- build-plugin.mjs now fails the build on a syntax error in the plugin UI/code (a '//' comment inside a one-line statement once killed the whole plugin silently). After editing scripts/plugin/ui.html always run `node scripts/build-plugin.mjs` and read its output.
- **Redesign propagation on hand-made (non-Clause) frames**: `swap.mjs` spec item `{target, donor, name?, texts:[[layerName,text,nth?]]}` replaces `target` with a clone of `donor` (the redesigned part) and retexts it; `{target, move:{anchor, alignRight?, dy?}}` re-anchors an overlay (menu) under a new trigger. Find old copies by scanning `look.mjs tree <frame> 12 | grep <part name>` per frame (section trees truncate at 1500 lines).
- `swap.mjs` `{target, copyFill:<donor>, strokes?:true}` copies fills (+outline) incl. bound variables from a redesigned layer — use for "same card, new colours" rollouts. Gotcha: `inspect --raw` does not report fill/stroke overrides on instances; diff two snaps too when a redesign "has no diff".
- Frames rebuilt from a hand-made screen: `inspect.mjs <id>` drafts a skeleton, then a throwaway generator (see `ds/files/clients/gen-templates.mjs`) rewrites it with catalog components. Catalog gotchas: private `_` sets (e.g. `_Tab base`) fail to import in other files — use the public wrapper (`horizontal-tabs`); text style keys come from `variable-keys.json`; `table-cell` "Icon with text and badge" hides its text by default (`show:true`) and its text placeholder is "$1,800"; `lint.mjs` now merges `extends` catalogs like compile.
- **Context budget**: scripts/ctx-budget.mjs measures start-up context (session-start prints it; limit ~9k tokens); docs/POWER-INDEX.md (generated by power-index.mjs) replaces reading the whole POWER-USE.md. Rules for tool output and images live in CLAUDE.md → Context budget.
- **Swap catalog components into non-Clause frames**: swap.mjs entries accept `comp` (catalog key) + `props`, `text`, `fill`, `hideTexts`; spec needs `ds` and `useComps`. Example scripts/variants/clients-ask-input.json.
- **Editing layers inside a swapped instance**: swap entries take `replaceTexts` [find,new,nth] (visible text only), `hide` [{name,nth|all,w?,prefix?}] (counts only rendered nodes; hidden variants' layers otherwise shift nth), `show`, `hideTexts`. Order inside swap: props → text → hide → replaceTexts. Landing-page composer: `copilot-desktop-input-box` Type Landing Page; Attachment Yes shows 5 attachment slots, hide all but one card. Examples scripts/variants/clients-newcontract-*.json.
- CSS: `font: <size>/<lh> inherit` is INVALID (inherit cannot be a family in the shorthand) and the whole declaration is silently dropped — buttons then keep the browser default (13px). Use font-family:inherit; font-size; line-height separately.
- Menus and popovers use the catalog `dropdown-menu` (Small = 3 items + divider + extra; Full = header + search + 16 items: hide the header/search/scroll bar and extra rows to get N items). Swap entries keep an absolute position (`wasAbs`); reposition with `move` (anchor id or anchorText+within) or `place`{x,y}. Examples scripts/variants/clients-dropdowns.json, clients-attach-menu.json, clients-menu-positions.json.
- **Chat chips follow replaced nodes**: swap jobs return `remap` (old id → new id); the server keeps .clause/idmap.json (GET /idmap) and the plugin resolves a chip's id through it before locating, so a chip for a replaced frame still jumps to its replacement while keeping the old chip label. Ids replaced before this (menus) were back-filled; earlier replacements (composers, Ask boxes) are not mapped.
- **Swap icons inside an instance** (e.g. dropdown items): swap entry with `icons`:[{item,key|comp,size?}] swaps each rendered item's placeholder instance (swapComponent). Company logos come from the All Company Logos library by raw key; there is no iManage logo, so a folder icon stands in. Example scripts/variants/clients-attach-icons.json.
- Listening banner: server counts Claude as listening for 45s after the last inbox poll (and while working); the plugin shows the banner only after 3 consecutive 'not listening' checks. Restarting the server kills the watcher: re-arm it right after any restart.
- Rebuilding a component variant from a reference frame: `swap.mjs` `{target, rebuild:{fillFrom, width?, children:[{donor, name, grow?, fillX?, pad?, hide?:[layer names], center?, props?:{"<Set name>":{Variant:"Collapsed"}}}]}}` empties the frame and fills it with donor clones; `{target, setProps:{paddingTop:15,…}}` sets raw node props. Gotchas: Nav_menu/Main collapsed default state is spelled `default` (lowercase); never setProperties on nested instance parts after a variant swap (stale ids).
- `swap.mjs` extra modes: `{target:<frame>, insert:{key|byName, name, fillX, remove:[child names], props, text, noFill}}` adds a library instance and removes old children only after it exists; `{target, edit:[{id, text?, visible?}]}` edits layers by id inside instances. Gotcha: `es-breadcrumb` is NOT published to the Clients file; use `breadcrumb-bar` (3 crumbs + Current Page; hide crumb+divider you do not need).
- `swap.mjs` donor-graft also takes `props` (e.g. {"Icon swap":"<component id>"}): clone a library instance (Small Icon Button) in place of a raw icon, then point its icon at the old icon component id (`inspect --raw` → mc.id).
- `swap.mjs` `{target:<card>, table:{tabs,header,cell,pill,columns}}` rebuilds a hand-made table card as column stacks of library instances (tabs, Col Header Cell, Table cell, Pill squared), reading texts/statuses from the live frame first; `{find:"regex"}` lists components local to the open file; setProps accepts `minHeight:null`. `Small Tabs` is local to the announcements file only — in other files use `horizontal-tabs` Size xs.
- Rolling the reference table design to all list screens: `node scripts/gen-tables.mjs <cardId…>` reads each live hand-made table card (tabs, header row, rows; kinds Text/Name/Source/Person/Status) and writes `$TMPDIR/tbl_<id>.json`, run each with `swap.mjs` (one at a time; the 11-row Requests card needs ~5 min). After: set status wrappers / tabs / card `layoutSizingVertical:"HUG"` (builder does it now), widen ID-like columns (padding is built into cells; `setProps {__w:<px>}` resizes). Name cells = `Icon with text and badge` with pill hidden, text shown, placeholder swapped to file-05.
- Re-propagating a designer tweak of a built table: diff with a probe (`swap.mjs {probe:[ids], deep:true}` returns fills/strokes/hidden layers that `inspect --raw` misses on instances), then apply with `copyFill`, `compProps`, `setProps`, or clone the changed frame with `donor` + `retext` + `hideNames` + `keep`; `moveTo` reorders children.
- Replacing a hand-made mini-component everywhere with a new DS component: `swap.mjs {findIn:{root,re}}` lists every match (id, screen), `{swapMarks:{map:{"<old name>":"<component id>"},ids}}` swaps frames for instances keeping index/size/layout (batch ≤50), `{swapComp:{to,ids}}` swaps existing instances (e.g. icon dots inside buttons) keeping size. Always re-run findIn after to confirm none remain.
- Replacing a hand-made segmented control with the DS `toggle-group`: `swap.mjs {replaceLib:[{target,key,props:{Type:"Inset",Style:"Icon with text",Size:"xs"},bases:[{text,icon:<icon component id>,current}]}]}` — segments are `_Toggle group base` children (6 slots, extras hidden); read which option is current from the old frame (white fill) first.
- Status cells in tables = `Table cell` Style "Badge single" (designer-made), never a wrapper frame around a Pill: `swap.mjs {badgeCells:{donor,items:[{target,text,color}]}}` clones the designer cell per row; `{target, remove:true}` deletes a node. Standing: use Badge single for any single-badge table cell.
- Hand-made menu frames → DS `Dropdown Menu` (Type Small): `swap.mjs {dropdownMenus:[{target,key,type,items:[{text,mark,selected}]}]}` keeps the overlay right edge and y; rows beyond the item list are hidden. Left as hand-made until asked: Filter menu (02) and Status menu (23).
- Figma comments: `node scripts/comments.mjs [--file <key|url>] [--all] [--json]` lists open comments (REST API). Token on the first line of `.clause/figma-token` (gitignored) or env FIGMA_TOKEN; file key remembered in `.clause/figma-file`. Needs scope file_comments:read.
- Onboarding sets up Figma comments: manifest has `enablePrivatePluginApi` so the plugin saves the file key to `.clause/figma-file`; the user saves a personal access token (comments + file read) as the only line of `.clause/figma-token`. Checked by `session-start`, `setup.mjs` and `/onboard` step 4b; read with `node scripts/comments.mjs`.
- Re-doing an old-style table on another screen from the reference: clone the reference card with `{target:<old card>, donor:<ref card>, keepOld:true}`, then `edit` ops (`copyFillFrom` for text colours, `compProps` for State, `moveInto` for nodes such as a row-actions button), `newFrames` for an extra column, `copyFill`+`strokes` for dividers, then `{remove:true}` the old card. Moved absolute nodes need `layoutPositioning:"AUTO"`.
- Updates: `node scripts/update-check.mjs [--force]` fetches the remote, fast-forwards only when the tree is clean with no local commits (then rebuilds the plugin), else records "behind". Runs at server start, every 3h, and in session-start; /status carries `update`, the plugin shows a one-line nudge. The "Claude isnt listening" toast is commented out in `scripts/plugin/ui.html`.
- Shared vs local: `.clause/role` = maintainer|user (default user). Users never write tracked files: corrections -> `.clause/local-rules.md`, registrations -> `.clause/registry.local.json` (`scripts/registry.mjs` merges it with ds/registry.json), new Figma files -> untracked `ds/files/<id>/`. `update-check.mjs` fast-forwards unless an incoming file was edited locally (generated figma-plugin/ is restored and rebuilt).
- `swap.mjs {splitColumns:[{column,idWidth,titleHeader}]}` turns a stacked id+title column into two columns (id muted, title main), keeping row order. Gotcha: `moveTo` index is the slot BEFORE removal (moving down one needs index+2); never reorder rows the designer arranged — inspect first.
- `swap.mjs {replaceText:{root,from,to}}` rewrites matching text layers (inside instances too) under a node; used for id prefix changes (RQ- -> REQ-).
- Journey board: `node ds/files/clients/journeys.mjs` writes one spec per journey (cover + cloned screens in flow order + dashed TO-CREATE placeholders carrying the prompt); run each with `swap.mjs` (row 0 creates the Section, the others need its id). Originals are never moved. Re-run for a new copy.
- `swap.mjs {menuIcons:[{menu,items:[{icon:<component id>,danger?}]}]}` sets leading icons on a Dropdown Menu instance (rows are instance children: cannot reorder/move rows or add a divider between them; the Divider variant is not available in this file).
- `swap.mjs {notCovered:{root,finding,clause}}` drops the Not-covered group header and replaces chevrons on those rows with the donor "Not covered" text (setTextStyleIdAsync needed under dynamic-page).
- Filter menu (clause list) = DS Dropdown Menu Type Small, 6 rows: icon (list or Mark), label, count in the Shortcut slot, "All clauses" Selected. Type Full adds a header + search, do not use.

- Chat chips follow rebuilt frames two ways: (1) every replacing swap job returns `remap:[{from,to}]` (server merges it into .clause/idmap.json; `resolveId` walks it); (2) fallback in the plugin `locate`: if the id is gone, pick the same-named node on the page, preferring the one sharing most ancestor names. Chips carry data-name/data-path.
- Toasts = DS `alert` (lib key variant 9797d40a…, Size sm, Color Default, Actions on, Icon/Supporting off) in explicit Dark mode: `swap.mjs {darkMode:{target}}` sets the dark mode of every colour collection used inside; shrink with setProps layoutSizingHorizontal FIXED + __w.
- Plugin shortcut: ⌘⇧K / Ctrl+Shift+K collapses or expands (expanding focuses the message box); re-running the plugin (⌘⌥P) while open also toggles via figma.on("run") (ignored for 2 s after start; untested on all Figma builds).
- Collapse/expand shortcut is user-set: default Alt+Shift+C (matched by physical key), change it in the plugin menu ("Collapse / expand shortcut", press the new keys, Esc cancels); stored in localStorage `collapseKey`. The old fixed Cmd+Shift+K clashed with a Figma shortcut.
- Canvas toggle: re-running the plugin (⌘⌥P "Run last plugin") collapses/expands it: a clientStorage heartbeat ("clause-alive", every 2 s) tells a new instance that the previous one just ran, so it toggles instead of just opening. The custom key combo only works while the plugin window has focus (Figma does not forward canvas keys to plugins).
- Plugin always opens expanded (no persisted collapsed state). A re-run while open (⌘⌥P) collapses it, or, if it was collapsed, expands + focuses the input; the main thread tracks `collapsedState` and writes it with the heartbeat.
- Each plugin run (⌘⌥P or menu "Open Clause Assist") flips the saved collapsed/expanded state (clientStorage "clause-ui"; first run expanded), shows the window and focuses the input on expand. "Start (silent)" does not touch it. Replaces the earlier heartbeat approach.
- (Reverted at the designer's request) start-up clamp of the plugin window into the visible canvas. Resize/expand still clamps inside viewport.bounds.
- ⌘⌥P / Ctrl+Alt+P is also handled inside the plugin window (it toggles collapse), because Figma never receives it while the window has focus; from the canvas Figma re-runs the plugin and the saved state flips.
- Collapsed plugin button: when the agent finishes a job (working -> idle, not stopped/error) it flashes blue for ~2 s with a drawn check, then returns to idle.
- Missing-clause state: the expanded missing clause carries an "Insert preferred wording" suggestion card (position pill header, green underlined wording, Edit with AI + Apply) under the We need block. `swap.mjs {missingCards:{card,green,details}}` clones the designer card (donor) and adapts it; run per Detail frame of expanded missing clauses.
